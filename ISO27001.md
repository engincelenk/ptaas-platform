## Überblick

ISO 27001 verlangt kein perfektes System — sondern ein **nachweisbares Information Security Management System (ISMS)**:

1. Risiken systematisch identifizieren und behandeln
2. Controls (Annex A) auswählen und dokumentieren
3. Wirksamkeit messen und kontinuierlich verbessern

Für eine Zertifizierung ist ein DAkkS-akkreditierter externer Auditor notwendig. Dieses Dokument dient als Umsetzungsplan für ISO-27001-Konformität als Entwicklungsgrundlage.

**ISO-DEV-01 — Audit Log Immutability**

Milestone: **M2**

Audit Log Einträge dürfen nie geändert oder gelöscht werden.

```sql
-- Kein DELETE/UPDATE auf audit_logs erlaubt
-- Option A: Row-Level Security (PostgreSQL)
ALTER TABLE audit_logs ENABLE ROW LEVEL SECURITY;
CREATE POLICY audit_logs_insert_only ON audit_logs
  FOR INSERT WITH CHECK (true);
-- Kein SELECT-Policy für UPDATE/DELETE → blockiert alle Änderungen

-- Option B: Trigger
CREATE OR REPLACE FUNCTION prevent_audit_modification()
RETURNS TRIGGER AS $$
BEGIN
  RAISE EXCEPTION 'Audit logs are immutable';
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER audit_logs_immutable
  BEFORE UPDATE OR DELETE ON audit_logs
  FOR EACH ROW EXECUTE FUNCTION prevent_audit_modification();
```

Anforderungen:
- Kein `UPDATE` oder `DELETE` auf `audit_logs` Tabelle — nur `INSERT`
- Keine Löschfrist für Audit Logs (36 Monate Aufbewahrung — scope.md)
- Implementierung in Prisma Migration als Teil von M2

  // Pfade mit potentiellen IDs ersetzen

  // ... Implementierung
  return { text: pseudonymizedText, map };
}

export function resubstitute(text: string, map: PseudonymMap): string {
  let result = text;
  for (const [original, placeholder] of Object.entries(map)) {

**ISO-DEV-03 — DSGVO Betroffenenrechte**

Milestone: **M6**

Fehlt bisher vollständig. Alle drei Endpoints sind DSGVO-Pflicht (Art. 15, 17, 20, 21).

```typescript
// Auskunftsrecht (Art. 15) + Datenportabilität (Art. 20)
GET /api/v1/me/export
→ JSON mit allen personenbezogenen Daten des Users
→ Inkl. Findings-Zugriffe, Audit Log Einträge, Profildaten

// Löschrecht (Art. 17) — Hard Delete
DELETE /api/v1/me
→ Vollständige Löschung aller Daten
→ Ausnahme: Audit Logs (gesetzliche Aufbewahrungspflicht)
→ Bestätigung via MFA-Code erforderlich

// Widerspruchsrecht (Art. 21) — Claude API Einwilligung
PATCH /api/v1/me/consent
body: { claudeApiAnalysis: false }
→ Deaktiviert KI-Analyse für diesen User
→ Findings werden ohne Claude-Analyse gespeichert
```

Anforderungen:
- Export-Endpoint liefert vollständiges JSON (alle Tabellen mit user_id)
- Hard-Delete kaskadiert korrekt durch alle Tabellen
- Consent-Flag in User-Tabelle, wird vor jedem Claude-API-Call geprüft
- Alle drei Aktionen werden im Audit Log erfasst

**ISO-DEV-04 — Secrets Rotation Mechanismus**

Milestone: **M6**

AES-256-GCM Encryption Key muss rotierbar sein ohne Datenverlust.

```typescript
// Rotation-Prozess:
// 1. Neuer Key wird als NEW_ENCRYPTION_KEY gesetzt
// 2. Admin triggert Rotation via internem Endpoint
// 3. Alle verschlüsselten Credentials werden mit altem Key entschlüsselt
//    und mit neuem Key re-enkryptiert
// 4. OLD_ENCRYPTION_KEY wird entfernt

// POST /internal/admin/rotate-encryption-key
// → Nur erreichbar aus internem Docker-Netzwerk
// → Ergebnis: X Credentials rotiert, im Audit Log erfasst
```

Anforderungen:
- Interner Endpoint (nicht öffentlich erreichbar)
- Transaktional: entweder alle Credentials rotiert oder keine
- Rotation-Event ins Audit Log
- Dokumentation des Rotation-Prozesses in `BACKUP_RESTORE.md`

**ISO-DEV-06 — pip-audit + SBOM in CI**

Milestone: **M1** (direkt in GitHub Actions)

```yaml
# .github/workflows/ci.yml — Ergänzung

- name: Python Dependency Audit
  run: |
    pip install pip-audit --break-system-packages
    pip-audit -r apps/scanner/requirements.txt --fail-on-vuln

- name: Generate SBOM (npm)
  run: npx @cyclonedx/cyclonedx-npm --output-file sbom.json

- name: Upload SBOM as Artifact
  uses: actions/upload-artifact@v4
  with:
    name: sbom
    path: sbom.json
```

Anforderungen:
- pip-audit schlägt CI fehl bei kritischen Vulnerabilities (nicht nur Warning)
- SBOM als CI-Artifact archiviert
- npm audit bereits vorhanden ✓

**ISO-DEV-08 — Vulnerability Disclosure Policy**

Milestone: **M7**

Öffentliche Seite `/security` mit:
- Scope: Was darf gemeldet werden
- Kontakt: security@[domain] (dedizierte Adresse)
